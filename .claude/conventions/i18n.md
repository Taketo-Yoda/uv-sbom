# Message Catalog Convention (canonical)

Single source of truth for where a new user-visible string goes. Established by
Issue #1055 (parent #952), after #1054 split the catalogs out of `src/i18n/mod.rs`;
the location was previously restated in `/implement`, `/code-review`, and the i18n
Specialist agent.

## Rule

Every new user-visible string (output via `eprintln!`/`println!`, or rendered by a
formatter) is added as a named key in all four places:

1. a field on `Messages` in `src/i18n/mod.rs`
2. an entry in `EN_MESSAGES` in `src/i18n/en.rs`
3. an entry in `JA_MESSAGES` in `src/i18n/ja.rs`
4. its name in `all_message_fields!` in `src/i18n/mod.rs`'s `mod tests`
   (compile-enforced; drives the EN/JA `{}` placeholder-count parity test)

If the JA template intentionally has fewer `{}` placeholders than EN, also add the
field to `PLACEHOLDER_MISMATCH_ALLOWLIST` in `src/i18n/mod.rs`'s tests and mark the
`JA_MESSAGES` entry with a `// JA:` comment explaining why.

Tests: EN-only tests go in `en.rs`, JA-only tests in `ja.rs`, and cross-locale tests
(placeholder parity and argument order) in `mod.rs`. General placement follows
`.claude/conventions/testing.md` → "Rule".

## Consumers

- `.claude/skills/implement/SKILL.md` Step 4 **i18n** bullet: forbids hardcoded
  output text and links here.
- `.claude/skills/code-review/SKILL.md` criterion 11: owns the review severities
  (this file only states the rule).
- `.claude/agents/i18n.md`: reads the three files when reviewing catalogs.
